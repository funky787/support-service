# Дефекты и регрессии

## 1. Ошибка фильтрации overdue=false

**Проблема:** заявки без срока выполнения не отображались при фильтрации `overdue=false`.

### Как воспроизвести

1. Создать заявку без поля `dueAt`.
2. Проверить, что заявка создалась со статусом `NEW`.
3. Отправить запрос `GET /api/tickets?overdue=false`.
4. Проверить, есть ли созданная заявка в результате.

**Ожидаемый результат:** заявка отображается, поскольку у неё нет срока выполнения и она не считается просроченной.

**Фактический результат до исправления:** заявка отсутствовала в списке.

### Причина

В SQL сравнение с `NULL` работает не как обычное сравнение значений. Из-за этого условие фильтрации не включало заявки, у которых `dueAt` равен `NULL`.

### Исправление

В `TicketService.java` добавил отдельную проверку `dueAt IS NULL` для фильтра `overdue=false`.

Теперь заявки без срока выполнения правильно попадают в список непросроченных.

### Проверка

Добавил интеграционный тест `ApiIntegrationTest.ticketWithoutDeadlineIsNotOverdue`.

Он создаёт заявку без срока и проверяет её наличие в ответе API при `overdue=false`.

После исправления тест проходит успешно.

**Статус:** исправлено.

**Pull Request:** https://github.com/funky787/support-service/pull/1

## 2. Проверка запрещённого перехода статуса

Отдельно проверял риск изменения истории при неправильной смене статуса.

### Проверка

1. Создать заявку со статусом `NEW`.
2. Попытаться перевести её сразу в `RESOLVED`.
3. Проверить ответ сервера.
4. Повторно запросить заявку и историю.

**Ожидаемый результат:** HTTP 409, статус остаётся `NEW`, история не изменяется.

**Тест:** `ApiIntegrationTest.forbiddenOperationKeepsStateAndHistory`.

**Результат:** проверка проходит успешно.

Это проверка бизнес-правила, а не обнаруженный дефект.тест проходит успешно.
