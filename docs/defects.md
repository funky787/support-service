# Дефекты и регрессии

Формат записи: ID, предусловия, шаги воспроизведения, ожидаемый результат, фактический результат, причина, исправление, тест, статус.

## Проверяемый риск: изменение истории при запрещённом переходе

Предусловие: новая заявка со статусом `NEW`.

1. Отправить `PATCH /api/tickets/{id}/status` с `{"status":"RESOLVED"}`.
2. Проверить HTTP 409.
3. Повторно получить заявку и историю.

Ожидаемое: статус `NEW`; история пуста. Регрессионная проверка: `ApiIntegrationTest.forbiddenOperationKeepsStateAndHistory`.

Это тест на известный риск, **не утверждение об обнаруженном в ходе выполнения дефекте**. Реальные найденные дефекты и красные тесты следует заносить сюда после запуска тестов.

## Ошибка фильтрации overdue=false

Заявки без срока выполнения не отображались при фильтрации overdue=false.

Причина: сравнение NULL в SQL.

Исправление: добавлена проверка dueAt IS NULL.

Регрессионный тест: ApiIntegrationTest.ticketWithoutDeadlineIsNotOverdue.

После исправления тест проходит успешно.
