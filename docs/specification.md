# Спецификация: сервис обработки заявок

## Проблема
Обращения в техподдержку поступают по разным каналам. Часть заявок теряется, сроки и статусы неудобно отслеживать.

## Пользователи
- Сотрудник: регистрирует обращение и проверяет его состояние.
- Специалист поддержки: просматривает, обрабатывает и закрывает заявки.
- Руководитель: проверяет статистику обращений.

## Границы проекта
Один REST API на Spring Boot с PostgreSQL. Интерфейс в браузере, авторизация и микросервисы не входят в обязательный объём.

## Пользовательские истории и критерии приёмки
1. Как сотрудник, я создаю заявку. При заполненных заголовке и категории API возвращает 201, а статус равен NEW.
2. Как сотрудник, я просматриваю заявку по ID. Существующая заявка возвращается с 200, неизвестная — с 404.
3. Как специалист, я меняю статус заявки. Допустимы NEW → IN_PROGRESS → RESOLVED и отмена из NEW или IN_PROGRESS; запрещённый переход даёт 409 без изменений.
4. Как специалист, я меняю описание, приоритет и срок. Для закрытой или отменённой заявки изменение запрещено.
5. Как специалист, я ищу заявки с фильтрацией и постраничным выводом. Результат соответствует параметрам запроса.
6. Как руководитель, я получаю сводку за период. В статистике учитываются только заявки, созданные в [from, to), а среднее время равно null, если завершённых нет.

## Функциональные требования
Создание, чтение, редактирование, переходы статусов, категории, поиск, история, отчёт.

## Нефункциональные требования
Повторяемый запуск, сохранность данных после рестарта, единый формат ошибок, никаких реальных секретов в репозитории.

## Контракт API
| Метод | URL | Назначение |
| --- | --- | --- |
| POST | /api/tickets | Создать заявку |
| GET | /api/tickets/{id} | Получить заявку |
| PUT | /api/tickets/{id} | Изменить описание, приоритет и срок |
| PATCH | /api/tickets/{id}/status | Изменить статус |
| GET | /api/tickets/{id}/history | История смены статусов |
| GET | /api/tickets | Фильтрация и пагинация |
| GET | /api/categories | Справочник категорий |
| GET | /api/reports/summary | Статистика |

Пример создания: `{"title":"Не работает принтер","categoryId":2,"priority":"HIGH"}` → `201 Created`, статус `NEW`.

Пример запрета: `PATCH /api/tickets/1/status` с `{"status":"RESOLVED"}` при `NEW` → `409`, данные неизменны.
